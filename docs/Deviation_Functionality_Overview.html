1. Overview

The parentDeviationCmp LWC sits on the Opportunity (Loan Application) record page. It lets a Credit/Sales user raise manual deviations against a Deviation master, tag them to a product and to the applicants they apply to, and capture mitigants. Automatic deviations are generated elsewhere and are shown (read-only) in the child list.

4. Approver Logic and Approval Status

  1. getDeviationApprover reads the loan's Branch_Master__c (Account).
  2. It finds the current user's AccountTeamMember on that branch with role Credit; Level__c is converted to an integer (digits only, e.g. "L2" → 2).
  3. For each deviation, the master-derived Approving_Authority__c is converted the same way. showApprovalButton = true only when the user's level >= required level; false if either is missing.
  4. changeApprovalStatus updates Approval_Status__c only if Mitigants__c is filled, else returns "Mitigants is required to be updated.".
  5. Automatic deviations show Approval Authority and Status as "-".
  6. Loan-level approval (HL_LoanApplicationApprovalController.checkIfAllDeviationsApproved) uses these deviations before final approval.

8. Observations from the Code

  • Parameter mismatch: handleSave calls createDeviationRecord with loanId, deviationId, deviationName, mitigants, deviationCategory, productId, but the Apex signature is (sanctionMaster, recordId, remark, appIds, mitigants, productId). handleSave appears unused; handleSaveManualDeviation matches.
  • Broken method: deleteMitigants uses removeMitigants (not imported) and an undefined Id variable.
  • SOQL injection risk: getDeviationMasterList concatenates searchText into dynamic SOQL without String.escapeSingleQuotes or bind variables.
  • Single-applicant selection bug: when only "Loan Application" exists, selectedValue is set to a string, not an array, then .length and String.join behave on a string/list mismatch.
  • Wire ordering: the Opportunity wire reads userProfile, which is populated by another wire and may still be empty on first run.
  • Editability: getComponentEditability ignores the component and profile arguments and only checks the sub stage label.
  • Hard-coded values: profile names, stage names and sub stages are literals in the LWC and Apex.
  • Fetch with null: checkSameDeviationadded and getApplicantsByLoanId have no try/catch; createDeviationRecord is not wrapped in AuraHandledException.
  • Duplicate code: handleDeviationSelction and handleDeviationSelection repeat the same logic; many console.log calls remain.
